# Deploy PromptCache to Render

`render.yaml` provisions four resources in the same Render region:

- `promptcache-dashboard`: public Nginx/React web service
- `promptcache-api`: FastAPI web service
- `promptcache-db`: private Render Postgres database
- `promptcache-cache`: private Render Key Value instance

The dashboard proxies `/v1/*` and `/health` to the API over Render's private network. Browser requests therefore stay on the dashboard origin, and provider API keys never enter the frontend image.

## 1. Prepare the repository

Push the branch containing `render.yaml` to a GitHub, GitLab, or Bitbucket repository connected to Render. Do not commit `.env`.

## 2. Generate the required encryption key

Run this once and save the output in your password manager:

```bash
python -c "import secrets,base64;print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

This value is the Fernet master key used to encrypt workspace provider credentials. Losing or changing it makes existing encrypted credentials unreadable.

## 3. Create the Blueprint

1. Open the Render Dashboard and choose **New > Blueprint**.
2. Connect this repository and select `render.yaml`.
3. During creation, provide these prompted values:
   - `API_KEY_ENC_MASTER_KEY`: the generated Fernet key; required.
   - `DASHBOARD_URL`: initially use the expected dashboard URL, such as `https://promptcache-dashboard.onrender.com`; correct it after creation if Render adds a suffix.
   - `CORS_ALLOW_ORIGINS`: the same dashboard URL. The same-origin proxy does not require CORS, but this permits direct browser API use from the dashboard domain.
   - Stripe variables: leave empty for the first smoke test, or enter Stripe test-mode values if billing is being tested immediately.
4. Review the estimated monthly cost and apply the Blueprint.

The Blueprint intentionally uses paid starter web/Key Value services and the smallest paid Postgres compute plan for a stable staging environment. Change plans in `render.yaml` if needed before creation.

`JWT_SECRET` and `ADMIN_API_KEY` are generated by Render. Do not replace them with the defaults from `.env.example`.

## 4. Verify the first deploy

The API container runs Alembic before starting Uvicorn. On a new database, the migration enables `pgvector` and creates the schema.

Check the API logs for:

```text
database migrations up to date
```

Then verify both public endpoints:

```bash
curl https://YOUR-DASHBOARD.onrender.com/
curl https://YOUR-DASHBOARD.onrender.com/health
curl https://YOUR-API.onrender.com/health
```

Each health request should return HTTP 200; the JSON response should include `"ok": true`.

After Render assigns the final URLs, update `DASHBOARD_URL` and `CORS_ALLOW_ORIGINS` on `promptcache-api` if the initial value differs, then redeploy the API.

## 5. Run the customer smoke test

1. Open the dashboard URL and create an account with a 12+ character password.
2. Create a workspace and save its generated `pc_...` API key.
3. Open **Settings**, connect a provider using a test-mode or low-limit provider key, and run **Test connection**.
4. Set the connected provider as the savings baseline.
5. Send a request through the dashboard's public URL:

```bash
curl https://YOUR-DASHBOARD.onrender.com/v1/chat/completions \
  -H "Authorization: Bearer pc_YOUR_WORKSPACE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"your-model","messages":[{"role":"user","content":"Reply with exactly: staging works"}]}'
```

6. Send the exact request again. Confirm the response's `promptcache.cached` value changes from `false` to `true`.
7. Refresh **Overview** and confirm requests, cache-hit rate, costs, and savings are populated.
8. Check **Analytics** for the request ledger and **Settings** for activation and audit events.
9. Regenerate the workspace key and confirm the old key returns HTTP 401.

## 6. Enable Stripe test billing (optional)

Create Startup, Growth, and Scale recurring prices in Stripe test mode. Set these API service variables in Render:

- `STRIPE_SECRET_KEY`
- `STRIPE_PRICE_STARTUP`
- `STRIPE_PRICE_GROWTH`
- `STRIPE_PRICE_SCALE`

Create a Stripe webhook endpoint:

```text
https://YOUR-API.onrender.com/v1/billing/webhook
```

Subscribe it to at least:

- `checkout.session.completed`
- `customer.subscription.created`
- `customer.subscription.updated`
- `customer.subscription.deleted`

Copy its signing secret to `STRIPE_WEBHOOK_SECRET`, redeploy the API, complete a test checkout, and confirm the dashboard plan changes after Stripe delivers the webhook.

## Operations notes

- Keep Postgres and Key Value private (`ipAllowList: []`).
- Configure Render deploy-failure and health-check notifications.
- Review API logs by request ID; production logs use JSON.
- Paid Render Postgres provides backups. Test a restore before onboarding real customer traffic.
- Rotate `ADMIN_API_KEY` and `JWT_SECRET` from the Render Dashboard if exposed.
- Never rotate `API_KEY_ENC_MASTER_KEY` without implementing a credential re-encryption procedure.
